## Архитектурное решение

###  Проблема и контекст
   В онлайн-магазине «Мобильный мир» коллекция products шардирована по составному ключу { category: 1, _id: 1 }. Категория «Электроника» оказалась настолько популярной, что генерирует 70% всех запросов к базе данных. Это привело к перегрузке одного из шардов, на котором размещены чанки с товарами данной категории.

Последствия:
* Деградация производительности запросов к популярным товарам
* Увеличение времени отклика для пользователей
* Риск отказа обслуживания при пиковых нагрузках
* Неравномерное использование ресурсов кластера

Для своевременного обнаружения дисбаланса нагрузки необходимо настроить комплексный мониторинг на базе Prometheus + Grafana с использованием mongodb_exporter

#### Дашборд Grafana (ключевые панели)
Обзор кластера: количество шардов, статус балансировщика, общее количество чанков
* Тепловая карта операций: QPS по шардам в реальном времени
* Распределение чанков: процентное соотношение чанков по шардам
* Горячие коллекции: топ-5 по чтению и записи
* Задержки операций: перцентили latency по каждому шарду

####  Настроить метрики:
Метрики уровня коллекций (Top Hottest Collections by Read, Top Hottest Collections by Write, Scanned Documents Rate)
Метрики производительности запросов (Operations Latency, COLLSCAN occurrences)
Метрики балансировки (Balancer Enabled)

Предложенная стратегия позволяет:
* Обнаруживать горячие шарды на ранней стадии с помощью комплексного мониторинга
* Реагировать автоматически через Zone Sharding и динамическую балансировку
* Предотвращать будущие проблемы через правильное проектирование шард-ключей
* Визуализировать состояние кластера в Grafana для оперативного контроля

Для категории «Электроника» рекомендуется выделить 2-3 шарда в отдельную зону, что равномерно распределит 70% нагрузки между ними и устранит «горячую» точку.
